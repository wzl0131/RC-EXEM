**工程**：`TEST` ｜ **主控**：STM32F427IIH6（大疆 A 板）
**技术栈**：STM32CubeMX + HAL + FreeRTOS + CAN + SBUS

# 一、任务与方案

## 1.1 考核要求要做什么

用大疆 A 板控制一个 M3508 电机（配 C620 电调），用遥控器操作两个模式：

```
SWA5 拨到最上面  →  位置控制：左摇杆 → 目标角度，推到底 = ±90°，中间线性
SWA5 拨到最下面  →  速度控制：右摇杆 → 目标转速，推到底 = 额定转速的 1/2，回中停止
SWA5 停在中间    →  停机
```

附加要求：
- 位置控制用**角度环 + 速度环串级**双环 PID
- 速度控制用**速度闭环** PID
- 整体用 **FreeRTOS**，自己定义任务
- 用 **J-Scope** 实时显示 5 条曲线（目标角度 / 实际角度 / 目标转速 / 实际转速 / PID 输出）
- 交完整代码仓库 + 这份说明文档

## 1.2 我的方案

**一句话：把"摇杆的位置"变成"电机的动作"，中间用串级 PID 和 CAN 连起来。**

```
   遥控器
     │ 2.4G
   接收机
     │ SBUS（反相串口）
     ▼
  USART1 中断 ──→ remote.ch[16]
                      │
                      ▼
              remoteTask (10ms)
              读遥控 + 判档位 + 算目标
                      │
                      ▼
              controlTask (1ms)
              保护 → 位置环 → 速度环 → 电流
                      │
                      ▼  CAN 控制帧
                  C620 电调 ──→ M3508 电机
                                   │
                          编码器反馈（1kHz）
                                   ▼
                          CAN1 中断 → motor1
                                   │
                    （回到 controlTask，闭环）
```

**具体做了四件事：**

| # | 做什么 | 怎么做的 |
|---|---|---|
| 1 | **两个任务分工** | `remoteTask`（10ms，次高优先级）只负责"读遥控 + 算目标"；`controlTask`（1ms，最高优先级）只负责"跑 PID + 发 CAN"。对应考核建议的"一个收遥控、一个控电机" |
| 2 | **串级 PID** | 位置环的**输出直接当速度环的目标**。位置环说"我要用 200rpm 转过去"，速度环负责不管负载怎样都达到这个速度 |
| 3 | **数据处理** | 遥控数据走 USART1 中断，电机反馈走 CAN 中断，控制计算在任务里，调试数据搬给 J-Scope。四条链路互不阻塞 |
| 4 | **保护** | 只做四条"真出事"的判断（遥控掉线 / 电调掉线 / 电调报错 / 过温），命中就断电流。**正常运行时它什么都不做** |

## 1.3 考核要求逐条对照

| 考核要求 | 实现 | 文件 |
|---|---|---|
| SWA5 上拨 → 位置控制，左摇杆 | 读 CH5 判档位 | `control.c` `ReadMode()` |
| 推到底 = ±90°，中间线性 | 摇杆归一化到 -1~+1 再乘 90 | `control.c` `Remote_ChNorm()` |
| 角度环 + 速度环串级 | 外环输出当内环目标 | `control.c` `Control_Update()` |
| SWA5 下拨 → 速度控制，右摇杆 | 同一个档位判断 | `control.c` |
| 推到底 = 1/2 额定，回中停 | 摇杆 × `CTRL_SPEED_LIMIT_RPM`(215) | `control.h` |
| 速度闭环 PID | 只跑速度环，跳过角度环 | `control.c` |
| 用调试软件看反馈图 | 5 个全局变量 + J-Scope | `debug.c` |
| FreeRTOS，自行定义任务 | 4 个任务 | `freertos.c` |
| 角度准确保持 ±90°，不过分抖动 | 串级 PID + 积分限幅 + 微分先行；保护不插手 | `pid.c` `protection.c` |
| 转速平稳正转 / 停 / 反转 | 速度环 + 目标值斜坡限速 | `control.c` |
| JScope 显示 5 条曲线 | `dbg_*` 五个变量 | `debug.c` |
| 交仓库 + 说明文档 | 本文件 | — |

# 二、硬件与接线

## 2.1 接线表

| 从 | 到 | A 板接哪个口 | 线 |
|---|---|---|---|
| 电池 24V | 分电板 | — | XT60 |
| 分电板 | A 板供电 | **接口 21**：`S8B-PH-SM4-TB`（8pin，"CAN1 输入和 24V 电源输入"）| 或用板子**背面备用 24V 焊盘** |
| 分电板 | C620 供电 | — | C620 电源线**兼容 XT30** |
| A 板 CAN1 | C620 的 CAN 口 | **接口 2**：`BM02B-GHS-TBT`（2pin GH1.25，共 5 个）| 自制 GH1.25 → C620 CAN 线 |
| 接收机 | A 板遥控口 | **接口 9**：DBUS 接口，在**板子右上角** | 配套线 |
| C620 | M3508 | — | **7-Pin 数据线** + **三相动力线**（颜色对应，别插反）|
| J-Link | A 板 SWD | **接口 14**：`Molex-53261-0471` | 4 根：3.3V / GND / SWDIO / SWCLK |

## 2.2 三个必须知道的点

**① A 板遥控口内置反相器，SBUS 接收机可以直接接**

A 板手册原文：

> "RM 开发板配备有 1 路遥控器接口，位于主控板右上角。遥控器到主控板使用的通信协议为 DBUS。
> **DBUS 是 UART 信号的反相形式**，因此从接插件的 1 脚进入后，会由**一个反相器反相**之后再进入 MCU。"
>
> 引脚配置表：**PB7（反相后）**

```
· 板上有反相器    → 反相的 SBUS 信号能直接接，不用外接反相器
· 反相后进 PB7    → PB7 = USART1_RX，和代码里配的 USART1 一致 ✓
· 大疆把这种反相串口叫 DBUS；HOTRC 接收机输出的 SBUS
  电气上几乎一样（100000 波特率 / 8 数据位 / 偶校验 / 2 停止位 / 反相 / 25 字节）
  → 所以能直接接
```

**② 24V 必须在其他线之前先接上**

C620 手册原文：

> "在电调电源线接通额定电压 24V 前，**禁止**通过其他端口（如 CAN 信号端口、PWM 信号端口）供电。"

**③ CAN 总线两端要各有一个 120Ω 终端电阻**

C620 那头自带一个，A 板这头要注意。没有终端电阻的话通信会不稳定。

## 2.3 上电顺序

```
第 1 步：先【不接】电机三相线和 7-Pin 线
第 2 步：接 24V（分电板 → A 板、分电板 → C620）
第 3 步：接 CAN（A 板接口 2 → C620 CAN 口）
第 4 步：接接收机（→ A 板接口 9）
第 5 步：接 J-Link（→ A 板接口 14）
第 6 步：下载程序 → 看绿灯闪不闪
第 7 步：确认没问题了，最后接电机的线和三相线
```

**为什么第 7 步才接电机**：万一 PID 参数不对，电机不会乱撞。

# 三、软件结构

## 3.1 分层

```
main.c          启动 + 上电自测 + 初始化
  │
freertos.c      4 个任务
  │
control.c       判档位 + 摇杆映射 + 串级 PID 调度      ← 核心
  │
  ├── protection.c   保护（4 条判断）
  ├── pid.c          PID 算法
  ├── can_motor.c    C620 的 CAN 收发 + 多圈角度
  └── remote.c       SBUS 解析
  │
debug.c         把 5 个量搬给 J-Scope
```

## 3.2 任务划分

| 任务 | 周期 | 优先级 | 干什么 | 对应考核建议 |
|---|---|---|---|---|
| `controlTask` | 1 ms | 40（High，最高）| 保护 + 双环 PID + 发 CAN | **输出控制电机** |
| `remoteTask` | 10 ms | 32（AboveNormal）| 读遥控 + 判档位 + 算目标 | **接收遥控器指令** |
| `debugTask` | 500 ms | 8（Low）| 绿灯心跳 | — |
| `defaultTask` | 1 ms | 24（Normal）| 空任务（CubeMX 模板留下的）| — |

`controlTask` 优先级最高，保证 1ms 控制周期不被别的任务拖慢。

## 3.3 启动流程

```
上电 / 复位
  │
  ├─ HAL_Init()                HAL 初始化 + 1ms 时基（用 TIM1）
  ├─ SystemClock_Config()      HSE 12MHz → PLL → 180MHz
  ├─ MX_GPIO_Init()            LED（PE11 / PF14）
  ├─ MX_CAN1_Init()            CAN1：PD0/PD1，1 Mbps
  ├─ MX_USART1_UART_Init()     USART1：SBUS 格式
  │
  ├─ 7 个上电自测（任何一个失败就红灯卡死，用闪法区分是哪个）
  │
  ├─ Control_Init()            初始化两路 PID + 保护
  ├─ C620_CanInit()            配滤波器 + Start + 开中断
  ├─ Remote_StartReceive()     挂上 USART1 单字节中断接收
  │
  ├─ osKernelInitialize()
  ├─ MX_FREERTOS_Init()        创建 4 个任务
  └─ osKernelStart()           启动调度器
```

**为什么自测放在启动接收之前**：如果先启动接收，电调的真实 CAN 帧会在自测的几十微秒里插进来，把自测用的假数据搅乱，会出现偶发的假失败，上机时很难查。

# 四、数据是怎么流动的（链路）

## 4.1 四条链路总览

```
① 遥控链路   遥控器 → 接收机 → USART1中断 → remote.ch[]        （10ms 一次算目标）
② 控制链路   controlTask → 双环PID → CAN发送 → 电调 → 电机      （1ms 一次）
③ 反馈链路   电调 → CAN接收中断 → motor1                        （1ms 一帧）
④ 调试链路   controlTask → dbg_* 五个变量 → J-Link 读内存 → J-Scope
```

## 4.2 链路一：遥控器 → 目标值

**函数调用链：**

```
遥控器 →(2.4G)→ 接收机 →(SBUS 反相串口)→ A 板接口9 → 反相器 → PB7(USART1_RX)
  │
  ▼ 每收到 1 个字节触发一次中断
USART1_IRQHandler()                    stm32f4xx_it.c
  └─ HAL_UART_IRQHandler()             HAL
        └─ HAL_UART_RxCpltCallback()   remote.c     ★ 在中断里执行
              ├─ Remote_FeedByte()     remote.c
              │     └─ 攒满 25 字节 → Remote_ParseFrame()   remote.c
              │           ├─ 校验帧尾
              │           ├─ 循环 16 次：GetBits(&buf[1], i*11, 11)   remote.c
              │           │     └─ 写 remote.ch[i]
              │           └─ 读标志位 → frame_lost / failsafe
              │              记 last_rx_tick，rx_count++
              └─ HAL_UART_Receive_IT()      ⭐ 必须重新挂上（它是一次性的）

出错路径：
USART1 出错 → HAL_UART_ErrorCallback()   remote.c
      └─ 重新挂 HAL_UART_Receive_IT()    ⭐ 不重挂 = 一次错误后永久收不到
```

**然后在 remoteTask 里解读：**

```
remoteTask()                           freertos.c    每 10ms
  └─ Control_RemoteUpdate()            control.c
        ├─ ReadMode()                  control.c
        │     读 remote.ch[4]（= CH5 = SWA5）
        │       > 1500 → POS     < 500 → SPEED     中间 → STOP
        │
        ├─ 档位变了 → Pid_Reset(两路)   pid.c   （清掉上一档攒的积分）
        │
        ├─ 位置模式：Remote_ChNorm() → ApplyDeadzone() → SlewLimit()
        │     → 写 s_target_deg
        │
        ├─ 速度模式：同上 → 写 s_stick_rpm
        │     另外 s_target_deg 跟着实际角度，并 Pid_SyncActual(&pid_angle)
        │
        └─ 停机模式：s_stick_rpm 斜坡到 0，s_target_deg 跟着实际角度
```

**这个任务只算目标，不跑 PID、不发 CAN。**

## 4.3 链路二：目标值 → 电机（核心）

```
controlTask()                          freertos.c    每 1ms
  │
  ├─ Control_Update()                  control.c
  │     │
  │     ├─【1】Protection_Update()      protection.c   返回允许的电流上限
  │     │      ├─ Remote_IsOnline()     remote.c       遥控在线吗（50ms 超时）
  │     │      ├─ M3508_IsOnline()      can_motor.c    电调在线吗（100ms 超时）
  │     │      ├─ motor1.err_code       电调报错了吗
  │     │      └─ motor1.raw_temp       过温了吗
  │     │
  │     │      返回 0 → C620_SendCurrent(1, 0) 立刻断电流
  │     │              Pid_Reset(两路) → return
  │     │
  │     ├─【2】位置环（只有位置模式）
  │     │      Pid_Calc(&pid_angle, s_target_deg, motor1.out_angle_deg, 0.001f)
  │     │      → target_rpm      ★ 外环的输出 = 内环的目标
  │     │      非位置模式：target_rpm = s_stick_rpm
  │     │      s_rpm_cmd = target_rpm   ← 给 J-Scope 用
  │     │
  │     ├─【3】速度环
  │     │      Pid_Calc(&pid_speed, target_rpm, motor1.out_rpm, 0.001f)
  │     │      → current
  │     │
  │     ├─【4】夹到保护给的限流上限
  │     ├─【5】电流变化率限制 SlewLimit()
  │     │
  │     └─【6】C620_SendCurrent(1, (int16_t)current)     can_motor.c
  │            ├─ 限幅到 ±16384
  │            ├─ 更新 static 数组 cur_buf[motor_id-1]
  │            ├─ 4 个 int16 拼成 8 字节（大端）
  │            ├─ 帧头：StdId = 0x200, DLC = 8
  │            └─ HAL_CAN_AddTxMessage()     HAL → CAN1 → 电调 → 电机
  │
  └─ Debug_Update()                    debug.c
        └─ 写 dbg_target_deg / dbg_actual_deg / dbg_target_rpm /
             dbg_actual_rpm / dbg_pid_out
```

## 4.4 链路三：电机 → 反馈

```
C620 每 1ms 发一帧（ID = 0x201，8 字节）
  │
  ▼
CAN1 硬件收到 → 过滤波器（掩码 0x7F0，只放行 0x200~0x20F）→ RX FIFO0 → 拉高中断
  │
  ▼
CAN1_RX0_IRQHandler()                        stm32f4xx_it.c
  └─ HAL_CAN_IRQHandler()                    HAL
        └─ HAL_CAN_RxFifo0MsgPendingCallback()   can_motor.c   ★ 中断里执行
              ├─ HAL_CAN_GetRxMessage()      HAL     把 8 字节搬出来
              └─ C620_ParseRx()              can_motor.c
                    ├─ 检查 ID 是不是 0x201
                    ├─ 大端解析 8 个字节
                    ├─ 多圈角度累计（第一帧 / 掉线恢复 / 正常，三种情况）
                    ├─ 单位换算（转子 → 输出轴）
                    └─ 记 last_rx_tick
  │
  ▼

```

## 4.5 链路四：数据 → J-Scope

```
controlTask 每 1ms → Debug_Update()      debug.c
  → 写 5 个全局 volatile 变量：
      dbg_target_deg   目标角度

      dbg_target_rpm   目标转速（位置模式下 = 位置环的输出）
```

# 五、关键实现点

## 5.1 串级 PID

```
位置环：输入（目标角度, 实际角度）→ 输出（目标转速）
速度环：输入（目标转速, 实际转速）→ 输出（电流）
```

位置环的输出直接当速度环的目标，这就是"串级"。

**为什么必须串级：** 只用角度环的话，同样的角度误差，空载和带负载需要的电流完全不同，参数根本调不出来。加上速度环之后，角度环只需要说"我要用 200rpm 转过去"，速度环负责不管负载怎样都达到这个速度。

## 5.2 减速比

编码器装在**转子**上（减速箱之前），但我们要控制的是**输出轴**（减速箱之后）。
减速比 19.2032 = 转子转 19.2032 圈，输出轴才转 1 圈。

```
输出轴角度 = 累计计数 ÷ 8192 × 360 ÷ 19.2032
输出轴转速 = 转子转速 ÷ 19.2032
```

手册里写明反馈的角度和转速都是**转子**的。

## 5.3 多圈角度累计

反馈角度只有 0~8191，转一圈归零，所以要一段一段累加。但过零时差值会突然变成 8000 多：

```
上次 8190，这次 5  →  原始差值 -8185
判定为正向跨零  →  加 8192  →  +7（正确）
```

阈值取 2048 / 6144（8192 的 1/4 和 3/4）。1kHz 采样、电机最快约 9000rpm，两次之间最多转 0.15 圈，远小于 1/4 圈。

**这个函数要处理三种情况：**

| 情况 | 怎么做 | 为什么 |
|---|---|---|
| **上电第一帧** | 把当前位置定为 0°，累计从 0 开始 | 全局变量上电是 0，电机可能实际停在 5000 的位置。不特殊处理的话第一帧差值算成 5000 → 角度变 11.4° → 位置环以为偏了 → 电机一上电自己动一下 |
| **掉线又恢复** | 只把 `last_raw_angle` 重新对到当前值，**不动累计值** | 掉线期间电机滑行了好几度，拿旧基准算差值会超出容忍范围（2048 计数），判断出错 → 角度乱掉 → 位置模式朝错误方向冲 |
| **正常连续收帧** | 正常累加 | — |

## 5.4 CAN 反馈帧的 8 个字节

手册规定（大端）：

| 字节 | 内容 |
|---|---|
| [0][1] | 转子机械角度 0~8191 |
| [2][3] | 转子转速 int16，rpm |
| [4][5] | 实际转矩电流 int16 |
| [6] | 温度 ℃ |
| [7] | 错误码，0 = 正常 |

角度用 `uint16_t` 读；转速和电流要强制转成 `int16_t` —— 同样的 16 位二进制，当无符号读是 65436，当有符号读是 -100，而它们是有正负的。

## 5.5 控制帧一帧装 4 个电调

`0x200` 这一帧里装电调 1~4 的电流（每台 2 字节）。所以不能只发一个电机，那样会把其他三个写成 0。代码里用一个 `static int16_t cur_buf[4]` 记住 4 台最近的值，每次一起发出去。

## 5.6 SBUS 的 16 个通道

一帧 25 字节：

| 字节 | 内容 |
|---|---|
| [0] | `0x0F` 帧头 |
| [1]~[22] | 16 个通道，每通道 11 位，连续打包 |
| [23] | 标志位（bit2 = 丢帧，bit3 = 失控保护）|
| [24] | `0x00` 帧尾 |

11 位没有按字节对齐，所以写了个 `GetBits()` 取位函数。
接收用"一字节一字节收 + 自己找帧头"的写法：丢字节能自动重新同步，而且自测可以直接喂假数据，不需要遥控器。

## 5.7 PID 的两个处理

**微分先行**：D 项对**测量值**微分，不对误差微分。不然摇杆（目标值）一跳变，D 项就会产生冲击。

**`Pid_Reset` 故意不清 `last_actual`**：清了的话 D 项会算出 `(当前值 - 0)/dt`，是个巨大的数。但位置环只在位置模式下被调用，所以非位置模式时要主动调 `Pid_SyncActual()` 把 `last_actual` 保持新鲜。

## 5.8 保护

只做四条"真出事"的判断，命中就返回"断电流"：

| 条件 | 阈值 |
|---|---|
| 遥控掉线 | 50ms 没收到 SBUS 帧，或接收机报失控保护 |
| 电调掉线 | 100ms 没收到 CAN 反馈 |
| 电调报错误码 | 手册第 8 字节 ≠ 0 |
| 电机过温 | ≥ 115℃（手册说电调自己到 125℃ 会报错，提前一点）|

**故意不做**降额、堵转检测、角度软限位、故障锁存。原因见 6.4。

# 六、调试中遇到的问题

## 6.1 电机一上电就自己动一下

**原因**：全局变量上电是 0，但电机实际可能停在 raw_angle = 5000 的位置。第一帧的差值算成 5000 - 0 = 5000，累计角度变成 11.4°，位置环以为偏了。

**解决**：第一帧只建立基准（把当前位置记成 0 度），不做累加。用 `inited` 标志区分。

## 6.2 从速度模式切回位置模式时会顿一下

**原因**：位置环只在位置模式下被调用，它的 `last_actual` 停在很久以前。切回来第一次计算，微分项是 `(当前角度 - 很久以前的角度) / 0.001`，非常大。

**解决**：加了 `Pid_SyncActual()`，非位置模式下每个周期把 `last_actual` 同步成当前角度。

## 6.3 拔掉 CAN 线电机不停

**原因**：用了一个 `online` 字段，只在收到帧时置 1，但没有任何地方把它清 0，所以永远是 1。"电调掉线"这条保护实际上从来没生效过。

**解决**：改成用 `last_rx_tick` 现算（`M3508_IsOnline()`），超过 100ms 没收到就算掉线。这样不会忘记更新。

## 6.4 一开始写的保护会误停电机

**原因**：原本加的三条"智能"保护，正好和考核要求冲突：

- **角度超出 90°+8° 就停机** → 位置环去 90° 本来就会超调，一超调就停了
- **堵转检测**（电流大 + 转速低持续 500ms）→ 位置模式"保持 90°"时转速本来就是 0，会被误判
- **过温降额** → 会削弱位置环的保持能力

**解决**：全删掉，只保留四类"真出事"的保护。

**这条改动的意义**：保护不是越多越好。**只在"必然出事"时动手，正常运行时绝不能插手。**

## 6.5 拔掉 CAN 线再插回来，角度会乱

**原因**：多圈累加是"这次的角度减上次的角度"。掉线期间保护把电流断了，电机会滑行好几度，但 `last_raw_angle` 还停在掉线前那一刻。恢复后第一帧拿旧基准算差值，位移超出了过零判断的容忍范围，判断出错 → 累计值一次跳错 → 角度乱掉 → 位置模式朝错误方向冲。

**解决**：在 `C620_ParseRx()` 里加一个判断 —— 如果离上次收到帧已经超过超时时间（说明刚掉线又恢复），就只把 `last_raw_angle` 重新对到当前值，**不动累计值**。这样角度不会跳，丢掉的只是掉线期间那点位移（本来也测不到）。

## 6.6 Keil 里中文注释变乱码

**原因**：Keil 编辑器默认按 GBK 打开文件，但文件是 UTF-8。

**解决**：把文件存成 UTF-8 **带 BOM**，Keil 就能正确识别。（新建的空文件没有 BOM，Keil 按西文处理，粘进去的中文会被丢掉。）
