## ⚠️ 1.7 不过（被狗误咬）怎么排查

```
① J-Scope 看 dbg_safety_fault  → 哪一位是 1？
     bit5/6/7（32/64/128）= 任务卡死
         → 心跳超时 200ms 太紧，改成 400ms（safety.h 里的 SAFETY_HB_TIMEOUT_MS）
         → 或者某个任务确实没在跑
     bit0~3 = 通信故障
         → 那是正常保护，不是误咬（通信故障照样喂狗，不会复位）
         
② J-Scope 看 dbg_safety_hb → 哪个字节大？
     第 0 字节（bit0-7）   = controlTask 的心跳年龄
     第 1 字节（bit8-15）  = remoteTask
     第 2 字节（bit16-23） = debugTask
```

# 第 3 组 ⭐ 核心新功能：任务卡死检测（15 分钟）

## 怎么造一个"任务卡死"

**在 `freertos.c` 的 `StartControlTask()` 里，临时加一行 `while(1);`：**

```c
  tick = osKernelGetTickCount();
  for(;;)
  {
    tick += 1U;
    osDelayUntil(tick);

    Safety_Heartbeat(SAFETY_TASK_CONTROL);

    while (1) { }          /* ⚠️ 临时加的测试代码，测完必须删！ */

    Control_Update();
    Debug_Update();
  }
```

## 预期现象（按时间顺序）

```
t = 0ms      进 while(1)，不喂狗了
t ≈ 200ms    安全中心判定 controlTask 卡死（但这时它自己也没在跑，
             ⭐ 实际上"通知"是靠不喂狗实现的）
t ≈ 500ms    ⭐ 看门狗咬 → 板子复位
t ≈ 500ms+   重新上电启动，绿灯重新开始闪
```

## 复位后立刻看这几项（⭐ 这就是"集中看到哪里出问题"）

| 变量 | 预期值 | 含义 |
|---|---|---|
| `dbg_safety_reset` 低 8 位 | **1** | ⭐ 是看门狗复位（不是上电）|
| `dbg_safety_reset` 高 8 位 | **2** | 第 2 次复位 |
| `dbg_safety_last_fault` | **32**（bit5）| ⭐ **是 controlTask 卡了** |
| `dbg_safety_fault_pc` | 0 | 不是 HardFault，所以没 PC |

**⭐⭐ 这一组过了，就证明学长说的"出现问题能集中看到哪里出问题了"真的实现了。**

## ⚠️ 注意

```
· 板子会一直"复位 → 卡死 → 复位"循环（因为 while(1) 还在）
· 测完【必须删掉那行 while(1)】，重新编译下载
· 如果不删就直接收工，明天就忘了 ⚠️
```

# 第 4 组：HardFault 记录（10 分钟）

## 怎么造一个 HardFault

**在 `main.c` 的自测之后（`/* USER CODE END 2 */` 之前）临时加：**

```c
    /* ⚠️ 临时测试代码，测完必须删！ */
    {
        void (*bad_func)(void) = (void (*)(void))0xFFFFFFFFU;
        bad_func();          /* 跳到非法地址 → HardFault */
    }
```

## 预期现象

```
① 红灯【常亮】（Safety_FaultHandler 里点亮的）
② 约 500ms 后看门狗复位
③ 复位后：
     dbg_safety_last_fault  含 bit4（16）
     dbg_safety_fault_pc    ⭐ 非 0 —— 这就是崩溃地址
     dbg_safety_reset 低8位 = 1（看门狗复位）
```

## ⭐ 拿到 PC 之后怎么查是哪崩的

```
① 打开 MDK-ARM\TEST\TEST.map
② 搜那个地址（比如 0x08001234）
③ 找它落在哪个函数的地址范围内
   → 就知道崩在哪个函数了

⭐ 面试时这一条很能打：
   "HardFault 的时候我把栈帧里的 PC 存进备份寄存器，
    复位后读出来去 map 文件里查，就知道崩在哪个函数。"
```
