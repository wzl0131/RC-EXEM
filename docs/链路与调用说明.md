# 一、系统总览

## 1.1 硬件连接

```
        电池 24V
           │
        分电板 ──┬──→ A 板（供电）
                └──→ C620 电调 ──三相线──→ M3508 电机
                          ↑
                   CAN 线（H 和 L）
                          │
   A 板 CAN1（PD0=RX / PD1=TX）
                          │
   A 板 P8 口 ←── SBUS 信号线 ──→ 接收机 ←(2.4G)─ HOTRC 遥控器
                          │
   A 板 SWD ←── J-Link / ST-Link ──→ 电脑（Keil 下载 / J-Scope 看曲线）
```

## 1.2 软件分层

```
┌──────────────────────────────────────────────────────────────────┐
│  main.c          启动 + 7 个上电自测 + 初始化                     │
├──────────────────────────────────────────────────────────────────┤
│  freertos.c      4 个任务 + 2 个 FreeRTOS 钩子                    │
│    ├─ remoteTask    ← 读遥控、判档位、算目标   （10 ms）          │
│    ├─ controlTask   ← 保护 + 串级 PID + 发 CAN （1 ms）           │
│    ├─ debugTask     ← 绿灯心跳                                   │
│    └─ defaultTask   ← 空（CubeMX 模板留下的）                     │
├──────────────────────────────────────────────────────────────────┤
│  control.c       档位判断 / 摇杆映射 / 斜坡限速 / 串级调度         │
│  protection.c    保护：掉线、报错、过温 → 断电流                  │
│  pid.c           PID 算法（微分先行 + 积分限幅）                  │
├──────────────────────────────────────────────────────────────────┤
│  remote.c        SBUS 协议解析（25 字节 → 16 通道）                │
│  can_motor.c     C620 协议：收发帧、大端解析、多圈角度             │
├──────────────────────────────────────────────────────────────────┤
│  debug.c         把 5 个量暴露给 J-Scope                          │
├──────────────────────────────────────────────────────────────────┤
│  HAL 库（CubeMX 生成）：can.c / usart.c / gpio.c / stm32f4xx_it.c │
└──────────────────────────────────────────────────────────────────┘
```

**⭐ 依赖方向（谁调用谁）：**

```
main.c
  └─→ control.c ──┬─→ protection.c ──→ remote.c / can_motor.c
                  ├─→ pid.c
                  └─→ can_motor.c
      debug.c ────┴─→ control.c / pid.c / can_motor.c
```

# 二、上电启动链路

## 2.1 从复位到调用 main()

```
① 上电 / 复位
      ↓
② 从 Flash 0x08000000 取【向量表】里的第 2 项（Reset 向量）
      ↓
③ 执行 Reset_Handler          【startup_stm32f427xx.s】
      ↓
④ 调用 SystemInit()            【system_stm32f4xx.c】—— 配时钟树基础
      ↓
⑤ 调用 __main()                【ARM 编译器提供的库函数】
      └─ 把 .data 段从 Flash 搬到 RAM；把 .bss 段清零
      ↓
⑥ 调用 main()                  【Core/Src/main.c】
```

> ⭐ 第 ⑤ 步就是"**全局变量自动清零**"发生的地方 —— 所以 `motor1`、`remote`、`protect`、`pid_speed` 开机时全是 0，不需要手动初始化。

## 2.2 main() 里面的顺序

```c
int main(void)                                          【Core/Src/main.c】
{
  HAL_Init();                     /* ① HAL 初始化 + 配 1ms 时基（用 TIM1）*/
  SystemClock_Config();           /* ② 时钟：HSE 12MHz → PLL → 180MHz */
  MX_GPIO_Init();                 /* ③ 引脚：LED_RED(PE11)、LED_GREEN(PF14) */
  MX_CAN1_Init();                 /* ④ CAN1：PD0/PD1、1 Mbps、开中断 */
  MX_USART1_UART_Init();          /* ⑤ USART1：SBUS 格式（100000/9B/EVEN/2） */

  /* ============ USER CODE BEGIN 2 ============ */

  /* ⑥ 七个上电自测（任何一个失败 → 红灯暗号 + 卡死）*/
  C620_SelfTest();                /* 红灯常亮   = CAN 大端解析错 */
  AngleAccumSelfTest();           /* 闪 500ms  = 过零累计错 */
  Pid_SelfTest();                 /* 闪 100ms  = PID 数学错 */
  Remote_SelfTest();              /* 闪 50ms   = SBUS 解析错 */
  Control_SelfTest();             /* 闪 200ms  = 档位/映射/限速错 */
  Protection_SelfTest();          /* 闪 300ms  = 保护判断错 */
  Debug_SelfTest();               /* 闪 400ms  = 数据搬运错 */

  /* ⑦ 初始化控制逻辑（两路 PID + 保护状态）*/
  Control_Init();                 /* 【control.c】*/

  /* ⑧ 自测全过 → 才启动接收 */
  C620_CanInit();                 /* 【can_motor.c】滤波器 + CAN_Start + 开中断通知 */
  Remote_StartReceive();          /* 【remote.c】挂上 USART1 单字节中断接收 */

  /* ============ USER CODE END 2 ============ */

  osKernelInitialize();           /* ⑨ 初始化 FreeRTOS 内核 */
  MX_FREERTOS_Init();             /* ⑩ 创建 4 个任务（只是登记，还没跑）*/
  osKernelStart();                /* ⑪ ⭐ 启动调度器 —— 从这里开始任务才真的跑 */
}
```

## 2.3 ⭐ 为什么自测要放在"启动接收之前"

```
如果先启动接收（C620_CanInit / Remote_StartReceive），
再跑自测：
   电调的真实 CAN 帧会在自测的几十微秒里插进来
   → 把自测用的假数据搅乱
   → 出现"偶发的假失败"（每次上电约 2% 概率）
   → 上机时会白白折腾

→ 所以顺序必须是：先自测，后启动接收
```

## 2.4 ⭐ 为什么 Control_Init() 也要放在启动接收之前

```
Control_Init() 里做两件事：
   ① Pid_Init(&pid_speed / &pid_angle)  —— 填参数 + 清状态
   ② Protection_Init()                  —— 清保护状态

而 remoteTask 和 controlTask 都会用到这些
→ 必须在两个任务跑起来之前初始化好
→ 否则任务用的是没初始化的 PID 参数（全 0）
```

# 三、CAN 接收链路（电调 → 单片机）

## 3.1 完整调用链

```
① C620 电调每 1 ms 往总线上发一帧
     STID = 0x201（= 0x200 + 电调ID 1），DLC = 8
              ↓  （两根线：CAN_H / CAN_L）
② A 板的 CAN1 硬件收到
     · 先过【滤波器】：掩码 0x7F0 → 只放行 0x200 ~ 0x20F
     · 8 个字节存进 RX FIFO0
     · 拉高中断请求线
              ↓
③ CPU 中断响应，查【向量表】
     startup_stm32f427xx.s  →  找到 CAN1_RX0_IRQHandler 的地址
              ↓
④ CAN1_RX0_IRQHandler()                        【Core/Src/stm32f4xx_it.c : 167】
     └─ HAL_CAN_IRQHandler(&hcan1);            ← ISR 里只有这一行
              ↓
⑤ HAL_CAN_IRQHandler()                         【HAL 库】
     · 读 CAN 的 IER/ESR/RF0R 寄存器
     · 判断出："RX FIFO0 收到新消息"
              ↓
⑥ HAL_CAN_RxFifo0MsgPendingCallback(hcan)      【Core/Src/can_motor.c】
     └─ HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &rx, data);
              ↓  （把 8 个字节从硬件邮箱搬到 data[]）
⑦ C620_ParseRx(rx.StdId, data)                 【Core/Src/can_motor.c】
     ├─ 检查 std_id 是不是 0x201，不是就 return -1
     ├─ 大端解析：data[0..7] → raw_angle / raw_rpm / raw_current / raw_temp / err_code
     ├─ M3508_UpdateAngle(m, m->raw_angle)     【Core/Src/can_motor.c】
     │     └─ 过零修正 + 累加 total_cnt
     ├─ 单位换算：out_angle_deg = total_cnt × CNT2DEG_OUT
     │            out_rpm       = raw_rpm   × ROTOR_RPM2OUT_RPM
     └─ 记时间戳：last_rx_tick = osKernelGetTickCount()
                  （在线判断靠它现算：M3508_IsOnline()）
              ↓
⑧ 结果就存在【全局变量 motor1】里
     （controlTask 会在下一个 1ms 周期里读它）
```

## 3.2 关键点

| 环节 | 文件 / 函数 | 说明 |
|---|---|---|
| 中断入口 | `stm32f4xx_it.c : CAN1_RX0_IRQHandler` | **CubeMX 生成**，不用改 |
| HAL 分发 | `HAL_CAN_IRQHandler` | HAL 库函数 |
| **你的回调** | `can_motor.c : HAL_CAN_RxFifo0MsgPendingCallback` | ⚠️ **函数名必须一字不差**，写错不报错但永远收不到 |
| 协议解析 | `can_motor.c : C620_ParseRx` | 大端、int16 转换、ID 过滤 |
| 多圈累计 | `can_motor.c : M3508_UpdateAngle` | 处理 8191→0 的过零 |
| 数据落点 | `motor1`（全局）| 读写都是 32 位，中断写/任务读，不需要锁 |

# 四、SBUS 接收链路（遥控器 → 单片机）

## 4.1 完整调用链

```
① 遥控器 →(2.4G)→ 接收机 →(SBUS 反相串口)→ A 板 P8 口
     · A 板 P8 口有【板载反相器】→ 信号变回普通 UART 电平
     · 接到 USART1_RX（PB7）
              ↓
② USART1 硬件每收到 1 个字节（每约 111 µs 一个）
     · 存进接收寄存器（只存 1 个字节）
     · 拉高中断请求线
              ↓
③ USART1_IRQHandler()                          【Core/Src/stm32f4xx_it.c : 195】
     └─ HAL_UART_IRQHandler(&huart1);          ← ISR 里只有这一行
              ↓
④ HAL_UART_IRQHandler()                        【HAL 库】
     · 判断出："这个字节收完了"
              ↓
⑤ HAL_UART_RxCpltCallback(huart)               【Core/Src/remote.c】
     ├─ Remote_FeedByte(rx_byte);              【remote.c】状态机喂一个字节
     └─ HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
           ⭐ 必须重新挂上！Receive_IT 是【一次性】的
              ↓
⑥ Remote_FeedByte(b)                           【Core/Src/remote.c】
     · rx_idx == 0 时：只接受帧头 0x0F，否则丢掉继续等
     · 攒满 25 个字节 → Remote_ParseFrame(rx_buf)
              ↓
⑦ Remote_ParseFrame(buf)                       【Core/Src/remote.c】
     ├─ 校验帧尾 buf[24] == 0x00，不对就整帧丢掉
     ├─ 循环 16 次：remote.ch[i] = GetBits(&buf[1], i*11, 11)
     │     └─ GetBits() 把连续打包的 11 位通道拆出来
     ├─ 读标志位 buf[23]：bit2 = frame_lost，bit3 = failsafe
     └─ 记时间戳 + remote.rx_count++
              ↓
⑧ 结果就存在【全局变量 remote】里（ch[0] ~ ch[15]）
```

## 4.2 出错时的路径

```
串口出帧错误 / 溢出 / 噪声
      ↓
HAL_UART_ErrorCallback(huart)                 【Core/Src/remote.c】
      └─ HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
            ⭐ 必须重新挂上！HAL 出错后会【自动关闭接收】，
               不重挂就是"一次错误 → 永久收不到数据，而且毫无提示"
```

# 五、遥控任务链路（remoteTask）

**周期：10 ms（100 Hz），优先级 `osPriorityAboveNormal`(32)**

```
MX_FREERTOS_Init()                             【Core/Src/freertos.c】
  └─ osThreadNew(startRemoteTask, NULL, &remoteTask_attributes)
              ↓  （osKernelStart() 之后才开始跑）
startRemoteTask(argument)                      【Core/Src/freertos.c】
  └─ for(;;) {
        tick += 10;  osDelayUntil(tick);       ← 严格 10ms 一次
        Control_RemoteUpdate();                【Core/Src/control.c】
     }
              ↓
Control_RemoteUpdate()                         【Core/Src/control.c】
  ├─ ReadMode()                                【control.c，内部函数】
  │     └─ 读 remote.ch[4]（= SBUS CH5 = SWA5）
  │        > 1500 → CTRL_MODE_POS
  │        <  500 → CTRL_MODE_SPEED
  │        中间   → CTRL_MODE_STOP
  │
  ├─ 如果档位变了：
  │     Pid_Reset(&pid_speed);  Pid_Reset(&pid_angle);   【pid.c】
  │     （清掉上一档位攒的积分，避免切档时冲击）
  │
  ├─ 位置模式：
  │     Remote_ChNorm(remote.ch[2])            【remote.c】通道值 → -1.0~+1.0
  │     ApplyDeadzone(...)                     【control.c】死区
  │     SlewLimit(s_target_deg, stick*90, 360, 0.01)  【control.c】斜坡限速
  │     → 写入全局 s_target_deg
  │
  ├─ 速度模式：
  │     Remote_ChNorm(remote.ch[1])
  │     ApplyDeadzone(...)
  │     SlewLimit(s_stick_rpm, stick*235, 600, 0.01)
  │     → 写入全局 s_stick_rpm
  │     s_target_deg = motor1.out_angle_deg   ← 位置目标跟着实际走
  │
  └─ 停机模式：
        s_stick_rpm 斜坡到 0；s_target_deg 跟着实际角度
```

**⭐ 这个任务只"算目标"，不发 CAN、不跑 PID。**

# 六、控制任务链路（controlTask）

**周期：1 ms（1 kHz），优先级 `osPriorityHigh`(40)，最高**

```
MX_FREERTOS_Init()                             【Core/Src/freertos.c】
  └─ osThreadNew(StartControlTask, NULL, &controlTask_attributes)
              ↓
StartControlTask(argument)                     【Core/Src/freertos.c】
  └─ for(;;) {
        tick += 1;  osDelayUntil(tick);        ← 严格 1ms（不累积漂移）
        Control_Update();                      【Core/Src/control.c】
        Debug_Update();                        【Core/Src/debug.c】
     }
              ↓
Control_Update()                               【Core/Src/control.c】
  │
  ├─【第 1 步】Protection_Update()              【Core/Src/protection.c】
  │     ├─ Remote_IsOnline()                   【remote.c】遥控在线吗？
  │     ├─ M3508_IsOnline()                    【can_motor.c】电调在线吗？
  │     ├─ 检查 motor1.err_code                电调报错码？
  │     ├─ 检查 motor1.raw_temp                过温 ≥115℃？
  │     └─ 返回 0 = 必须断电流 / 返回 16384 = 不限制
  │
  │     如果返回 0：
  │        C620_SendCurrent(1, 0);             【can_motor.c】立刻断电流
  │        Pid_Reset(&pid_speed / &pid_angle); 【pid.c】
  │        目标跟上实际值；return
  │
  ├─【第 2 步】位置环（只有位置模式）
  │     target_rpm = Pid_Calc(&pid_angle,
  │                            s_target_deg,          ← 目标角度（remoteTask 算的）
  │                            motor1.out_angle_deg,  ← 实际角度（CAN 中断填的）
  │                            dt = 0.001f);          【pid.c】
  │     → 输出 = 目标转速（这就是"串级"的接口）
  │
  │     非位置模式：target_rpm = s_stick_rpm
  │
  │     s_rpm_cmd = target_rpm;                 ← 给 J-Scope 画曲线用
  │
  ├─【第 3 步】速度环
  │     current = Pid_Calc(&pid_speed,
  │                        target_rpm,            ← 内环目标 = 外环输出
  │                        motor1.out_rpm,        ← 实际转速
  │                        dt = 0.001f);          【pid.c】
  │
  ├─【第 4 步】夹到保护给的限流上限
  │     if (current > limit) current = limit;  ...
  │
  ├─【第 5 步】电流变化率限制
  │     current = SlewLimit(s_last_current, current, 200000, 0.001f);
  │
  └─【第 6 步】发出去
        C620_SendCurrent(1, (int16_t)current);   【can_motor.c】
              ↓
              Debug_Update()                     【debug.c】
                └─ 把 5 个量写进 dbg_target_deg / dbg_actual_deg /
                   dbg_target_rpm / dbg_actual_rpm / dbg_pid_out
                   （J-Scope 直接读这 5 个变量）
```

## 6.1 ⭐ 串级 PID 的数据流（最重要的一张图）

```
   遥控器左摇杆
        ↓ Remote_ChNorm + 死区 + 斜坡
   s_target_deg  ──────────────────┐
   （remoteTask 算）                │
                                   ▼
                        ┌──────────────────────┐
   motor1.out_angle_deg │  位置环 Pid_Calc      │
   （CAN 中断填）  ─────→│  Pid_Calc(&pid_angle) │
                        └──────────┬───────────┘
                                   │ 输出 = 目标转速
                                   ▼
   s_rpm_cmd（也是 J-Scope 看的"目标转速"）
                                   │
                                   ▼
                        ┌──────────────────────┐
   motor1.out_rpm       │  速度环 Pid_Calc      │
   （CAN 中断填）  ─────→│  Pid_Calc(&pid_speed) │
                        └──────────┬───────────┘
                                   │ 输出 = 电流值
                                   ▼
                            C620_SendCurrent()
                                   ↓
                              电调 → 电机
```

# 七、CAN 发送链路（单片机 → 电调）

```
Control_Update()                               【Core/Src/control.c】
  └─ C620_SendCurrent(1, current)              【Core/Src/can_motor.c】
       ├─ 检查 motor_id 是否在 1~4
       ├─ 限幅到 ±16384
       ├─ 更新 static 数组 cur_buf[motor_id-1] = current
       │     ⭐ 一帧控制帧装 4 个电调的电流，所以要用 static 记住其他三个
       ├─ 把 4 个 int16 拼成 8 字节（大端）：
       │     data[i*2]   = 高字节 = (uint16)buf >> 8
       │     data[i*2+1] = 低字节 = (uint16)buf & 0xFF
       ├─ 填帧头：StdId = 0x200（控制电调 1~4），IDE = STD，
       │          RTR = DATA，DLC = 8
       └─ HAL_CAN_AddTxMessage(&hcan1, &tx, data, &mailbox);   【HAL 库】
              ↓
          CAN1 硬件把这一帧发到总线上
              ↓
          C620 电调收到 → 驱动 M3508 电机
```

# 八、调试数据链路（J-Scope）

```
controlTask 每 1ms：
    Control_Update()  →  Debug_Update()        【Core/Src/debug.c】
                              │
                              ├─ dbg_target_deg = Control_GetTargetDeg()   【control.c】
                              ├─ dbg_actual_deg = motor1.out_angle_deg     【can_motor.c 填的】
                              ├─ dbg_target_rpm = Control_GetTargetRpm()   【control.c】
                              ├─ dbg_actual_rpm = motor1.out_rpm           【can_motor.c 填的】
                              └─ dbg_pid_out    = pid_speed.output         【pid.c 填的】
                              ↓
                    （这 5 个是全局 volatile 变量）
                              ↓
        J-Link 通过【调试口直接读 RAM】  ← 目标板不需要写任何通信代码
                              ↓
                         J-Scope 画波形
```

**⭐ 对应考核要求原文：**

# 十一、中断与任务的边界

## 11.1 哪些代码在【中断】里跑

| 中断 | 入口 | 最终执行的我的代码 | 做什么 |
|---|---|---|---|
| CAN1_RX0 | `CAN1_RX0_IRQHandler` | `HAL_CAN_RxFifo0MsgPendingCallback` → `C620_ParseRx` → `M3508_UpdateAngle` | 读 8 字节 + 解析 + 累加 |
| USART1 | `USART1_IRQHandler` | `HAL_UART_RxCpltCallback` → `Remote_FeedByte` →（收满时）`Remote_ParseFrame` → `GetBits` | 攒帧 + 拆通道 |
| USART1 错误 | 同上 | `HAL_UART_ErrorCallback` | 重新挂接收 |
| TIM1_UP | `TIM1_UP_TIM10_IRQHandler` | `HAL_TIM_PeriodElapsedCallback` → `HAL_IncTick` | HAL 时基 +1ms |

**⭐⭐ 中断里的铁律：**
```
✗ 不能调用 osDelay() / osMutexAcquire() / 任何会阻塞的 RTOS API
✗ 不能 printf() / malloc()
✓ 只能做纯计算和寄存器操作（微秒级完成）
```

## 11.2 哪些代码在【任务】里跑

| 任务 | 周期 | 优先级 | 执行我的代码 |
|---|---|---|---|
| `remoteTask` | 10 ms | 32 (AboveNormal) | `Control_RemoteUpdate` |
| `controlTask` | 1 ms | 40 (High) | `Control_Update` + `Debug_Update` |
| `debugTask` | 500 ms | 8 (Low) | 绿灯翻转 |
| `defaultTask` | 1 ms | 24 (Normal) | 空 |

## 11.3 中断优先级配置（必须遵守 FreeRTOS 规则）

```
FreeRTOSConfig.h:
  configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5
  → 会调用 RTOS API 的中断，优先级【数字】必须 ≥ 5

实际配置：
  CAN1_RX0_IRQn  = 5   ✓（回调里用了 osKernelGetTickCount）
  USART1_IRQn    = 5   ✓（同上）
  TIM1_UP        = 15  ✓
```

# 十二、全局变量读写关系

| 全局变量 | 定义在哪 | 谁【写】 | 谁【读】 |
|---|---|---|---|
| `motor1` | `can_motor.c` | CAN 中断（`C620_ParseRx`）| controlTask、protection、debug、remoteTask |
| `remote` | `remote.c` | USART1 中断（`Remote_ParseFrame`）| remoteTask、protection、自测 |
| `protect` | `protection.c` | controlTask（`Protection_Update`）| debug |
| `pid_speed` / `pid_angle` | `pid.c` | remoteTask / controlTask（`Pid_Calc`）| debug、自测 |
| `s_mode` / `s_target_deg` / `s_stick_rpm` | `control.c`（static volatile）| **remoteTask** | **controlTask** |
| `s_rpm_cmd` / `s_last_current` | `control.c`（static）| controlTask | debug |
| `dbg_*` 5 个 | `debug.c` | controlTask（`Debug_Update`）| **J-Scope（外部读内存）** |

**⭐ 为什么不需要互斥锁：**
```
① 所有变量都是 32 位 → ARM 上单条指令读写，本身是原子的
② 都是"单写单读"结构，没有"两边同时写同一个变量"的情况
③ 共享变量都加了 volatile → 编译器不会把它缓存在寄存器里

⚠️ 如果以后要传结构体 / 数组（多字节），就必须加锁或用队列
```

# 附录：常见问题的定位顺序

| 现象 | 先查什么 |
|---|---|
| 绿灯不闪 | 程序没跑起来 → 检查下载、`main()` 里的自测是否卡住 |
| 红灯常亮 | `C620_SelfTest` 失败 或 **栈溢出** |
| 红灯闪 N ms | 对 `main.c` 里第 N 个自测（见 2.2 节的自测列表）|
| `M3508_IsOnline()` 返回 0 | CAN：24V 有没有接？滤波器（0x7F0）？回调函数名拼写？电调 ID 是不是 1？<br>（它读 `motor1.inited` + `last_rx_tick`，100ms 没帧就算掉线）|
| `remote.rx_count` 不涨 | SBUS：P8 口接线？波特率 100000？9B/EVEN/2 停止位？ |
| 电机不动但其余正常 | `remote.ch[4]`（SWA）值对不对？`protect.fault` 是不是非 0？ |
| 电机方向反了 | `control.c` 里目标值取反 |
| 角度到不了 90° | 位置环 `PID_ANGLE_OUT_MAX` 太小 / `PID_ANGLE_KP` 太小 |
| 角度抖动 | 位置环 `Kd` 调大 / 速度环 `Kp` 调小 |
