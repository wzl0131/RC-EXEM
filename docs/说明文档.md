# 电控考核 说明文档

**工程**：`TEST` ｜ **主控**：STM32F427IIH6（大疆 A 板）｜ **框架**：FreeRTOS + HAL

用遥控器（SBUS）操作两个模式：**位置控制**（角度环 + 速度环串级 PID）和**速度控制**（速度环）。
位置环的输出直接当速度环的目标，速度环的输出作为电流通过 CAN 发给 C620 电调。

本文档分三部分：**链路**（数据流过哪些函数）、**函数**（每个函数做什么、谁调用它）、**调用的逻辑**（为什么这么分层调用）。

---

# 一、链路

## 1.1 四条链路总览

```
① 遥控链路   遥控器 → 接收机 → USART1中断 → remote.ch[]           每帧触发
② 控制链路   controlTask → 双环PID → CAN发送 → 电调 → 电机         每 1ms
③ 反馈链路   电调 → CAN接收中断 → motor1                          每 1ms
④ 调试链路   controlTask → dbg_* 五个变量 → J-Link 读内存 → J-Scope  每 1ms
```

**四条链路的分工：**
- ①②③ 是控制闭环：遥控给目标 → 控制算电流 → 电机反馈回来
- ④ 只是"看"，不参与控制（整个 debug 模块删掉也不影响电机）

## 1.2 链路一：遥控器 → 目标值

### 1.2.1 从硬件到 remote.ch[]

```
遥控器 →(2.4G)→ 接收机 →(SBUS 反相串口)→ A 板遥控口 → 板载反相器 → PB7(USART1_RX)
  │
  ▼ 每收到 1 个字节触发一次中断
USART1_IRQHandler()                       stm32f4xx_it.c
  └─ HAL_UART_IRQHandler()                HAL 库
        └─ HAL_UART_RxCpltCallback()      remote.c        ★ 在中断里执行
              │
              ├─ Remote_FeedByte(rx_byte) remote.c
              │     │  状态机：rx_idx == 0 时只接受帧头 0x0F，否则丢掉重新等
              │     └─ 攒满 25 字节时
              │           Remote_ParseFrame(buf)          remote.c
              │             ├─ 校验帧尾 buf[24] == 0x00
              │             ├─ 循环 i = 0~15：
              │             │     remote.ch[i] = GetBits(&buf[1], i*11, 11)
              │             │                        └─ GetBits()  remote.c
              │             ├─ 读 buf[23] 的标志位
              │             │     → remote.frame_lost / remote.failsafe
              │             └─ 记 remote.last_rx_tick，remote.rx_count++
              │
              └─ HAL_UART_Receive_IT(&huart1, &rx_byte, 1)
                    ⭐ 必须重新挂上：Receive_IT 是一次性的，
                       不重挂就只收得到第一个字节

出错时的分支：
USART1 出错（帧错误 / 溢出）→ HAL_UART_ErrorCallback()    remote.c
      └─ 重新挂 HAL_UART_Receive_IT()
            ⭐ 不重挂 = 一次错误之后永久收不到数据，而且没有任何提示
```

### 1.2.2 从 remote.ch[] 到目标值

```
remoteTask(void *argument)                  freertos.c     每 10ms
  └─ Control_RemoteUpdate()                 control.c
        │
        ├─ ReadMode()                       control.c
        │     读 remote.ch[4]（= CH5 = SWA5）
        │       > 1500  →  CTRL_MODE_POS
        │       <  500  →  CTRL_MODE_SPEED
        │       中间    →  CTRL_MODE_STOP
        │
        ├─ 如果档位和上一周期不同：
        │     Pid_Reset(&pid_speed)                   pid.c
        │     Pid_Reset(&pid_angle)                   pid.c
        │     s_mode = mode
        │
        ├─ 位置模式：
        │     Remote_ChNorm(remote.ch[2])             remote.c   172~1811 → -1.0~+1.0
        │     ApplyDeadzone(...)                      control.c  消死区
        │     SlewLimit(s_target_deg, stick*90, 360, 0.01f)      control.c
        │     → 写 s_target_deg
        │     s_stick_rpm = 0
        │
        ├─ 速度模式：
        │     Remote_ChNorm(remote.ch[1])
        │     ApplyDeadzone(...)
        │     SlewLimit(s_stick_rpm, stick*215, 600, 0.01f)
        │     → 写 s_stick_rpm
        │     s_target_deg = motor1.out_angle_deg
        │     Pid_SyncActual(&pid_angle, motor1.out_angle_deg)   pid.c
        │
        └─ 停机模式：
              s_stick_rpm 斜坡到 0
              s_target_deg = motor1.out_angle_deg
              Pid_SyncActual(&pid_angle, motor1.out_angle_deg)
```

**本链路出口：`s_mode` / `s_target_deg` / `s_stick_rpm` 三个全局变量。**

## 1.3 链路二：目标值 → 电机（核心链路）

```
controlTask(void *argument)                 freertos.c     每 1ms
  │
  ├─ Control_Update()                       control.c
  │     │
  │     ├─【1】Protection_Update()           protection.c  算本次允许的电流上限
  │     │      ├─ Remote_IsOnline()          remote.c      遥控在线吗（50ms 超时）
  │     │      ├─ M3508_IsOnline()           can_motor.c   电调在线吗（100ms 超时）
  │     │      ├─ 读 motor1.err_code         电调报错误码了吗
  │     │      └─ 读 motor1.raw_temp         过温了吗（≥115℃）
  │     │
  │     │      返回 0（有故障）：
  │     │        C620_SendCurrent(1, 0)      can_motor.c   立刻断电流
  │     │        Pid_Reset(&pid_speed)       pid.c
  │     │        Pid_Reset(&pid_angle)       pid.c
  │     │        return（本周期结束）
  │     │
  │     ├─【2】位置环（只有位置模式才跑）
  │     │      Pid_Calc(&pid_angle,          pid.c
  │     │               s_target_deg,           ← 外环目标（链路一算的）
  │     │               motor1.out_angle_deg,   ← 外环反馈（链路三填的）
  │     │               0.001f)                 ← dt = 1ms
  │     │      → target_rpm                  ★ 外环的输出 = 内环的目标
  │     │
  │     │      非位置模式：target_rpm = s_stick_rpm
  │     │      s_rpm_cmd = target_rpm        ← 存下来给 J-Scope 看
  │     │
  │     ├─【3】速度环
  │     │      Pid_Calc(&pid_speed,          pid.c
  │     │               target_rpm,             ← 内环目标（外环输出）
  │     │               motor1.out_rpm,         ← 内环反馈
  │     │               0.001f)
  │     │      → current
  │     │
  │     ├─【4】夹到保护给的限流上限
  │     │
  │     ├─【5】SlewLimit(s_last_current, current, 1000000, 0.001f)   control.c
  │     │      限制电流变化率，避免切档位时电流一步跳到底
  │     │
  │     └─【6】C620_SendCurrent(1, (int16_t)current)    can_motor.c
  │            ├─ 检查 motor_id 在 1~4
  │            ├─ 限幅到 ±16384
  │            ├─ 更新 static 数组 cur_buf[motor_id-1]
  │            │     ⭐ 一帧控制帧装 4 个电调的电流，所以要用 static 记住其他三个
  │            ├─ 4 个 int16 拼成 8 字节（大端）
  │            ├─ 填帧头：StdId=0x200, IDE=STD, RTR=DATA, DLC=8
  │            └─ HAL_CAN_AddTxMessage(&hcan1, &tx, data, &mailbox)   HAL
  │                  ↓
  │              CAN1 硬件 → 总线 → C620 电调 → M3508 电机
  │
  └─ Debug_Update()                         debug.c
        ├─ dbg_target_deg = Control_GetTargetDeg()   control.c
        ├─ dbg_actual_deg = motor1.out_angle_deg     can_motor.c 填的
        ├─ dbg_target_rpm = Control_GetTargetRpm()   control.c
        ├─ dbg_actual_rpm = motor1.out_rpm           can_motor.c 填的
        └─ dbg_pid_out    = pid_speed.output         pid.c 填的
```

### 1.3.1 串级 PID 的数据流

```
   遥控器左摇杆
        │ Remote_ChNorm + ApplyDeadzone + SlewLimit（在 remoteTask 里做）
        ▼
   s_target_deg ──────────────────┐
                                  ▼
                    ┌──────────────────────────────┐
   motor1.out_angle_deg ──→│ 位置环 Pid_Calc(&pid_angle)  │
   （链路三填的）           └──────────────┬───────────────┘
                                          │ 输出 = 目标转速
                                          ▼
                                 s_rpm_cmd（也是 J-Scope 看的"目标转速"）
                                          │
                                          ▼
                    ┌──────────────────────────────┐
   motor1.out_rpm ────────→│ 速度环 Pid_Calc(&pid_speed)  │
   （链路三填的）           └──────────────┬───────────────┘
                                          │ 输出 = 电流值
                                          ▼
                                 C620_SendCurrent() → 电调 → 电机
                                          │
                                          └──→ 反馈回到 motor1（闭环）
```

## 1.4 链路三：电机 → 反馈

```
C620 电调每 1ms 主动发一帧（ID = 0x201，DLC = 8）
  │
  ▼ CAN 总线（CAN_H / CAN_L）
A 板 CAN1 硬件收到
  ├─ 先过【滤波器】：掩码 0x7F0 → 只放行 0x200 ~ 0x20F
  ├─ 8 个字节存进 RX FIFO0
  └─ 拉高中断请求线
  │
  ▼
CAN1_RX0_IRQHandler()                       stm32f4xx_it.c
  └─ HAL_CAN_IRQHandler(&hcan1)             HAL 库
        └─ HAL_CAN_RxFifo0MsgPendingCallback()    can_motor.c   ★ 在中断里执行
              │
              ├─ HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &rx, data)   HAL
              │     把 8 个字节从硬件邮箱搬到 data[]
              │
              └─ C620_ParseRx(rx.StdId, data)     can_motor.c
                    ├─ 检查 std_id 是不是 0x201，不是就 return -1
                    ├─ 大端解析 8 个字节 → raw_angle / raw_rpm /
                    │                      raw_current / raw_temp / err_code
                    ├─ 多圈角度累计（分三种情况）：
                    │     · inited == 0（上电第一帧）
                    │         last_raw_angle = raw_angle
                    │         total_cnt = 0
                    │         inited = 1
                    │     · 距上次收帧超过超时（掉线又恢复）
                    │         last_raw_angle = raw_angle（只重对基准，不动累计）
                    │     · 其他（正常连续收帧）
                    │         M3508_UpdateAngle(m, m->raw_angle)     can_motor.c
                    │               └─ 过零修正 + 累加 total_cnt
                    ├─ 单位换算：
                    │     out_angle_deg = total_cnt × CNT2DEG_OUT
                    │     out_rpm       = raw_rpm   × ROTOR_RPM2OUT_RPM
                    └─ 记 last_rx_tick = osKernelGetTickCount()
  │
  ▼
结果全部写进全局变量 motor1
  （controlTask 的下一个 1ms 周期读它 → 形成闭环）
```

## 1.5 链路四：数据 → J-Scope

```
controlTask 每 1ms → Debug_Update()              debug.c
  → 写 5 个全局 volatile 变量：
      dbg_target_deg   目标角度
      dbg_actual_deg   实际角度
      dbg_target_rpm   目标转速（位置模式下 = 位置环的输出）
      dbg_actual_rpm   实际转速
      dbg_pid_out      速度环输出 = 发给电调的电流
  │
  ▼
J-Link 通过调试口【直接读 RAM】—— 目标板不需要写任何通信代码
  │
  ▼
J-Scope 画波形（HSS 模式：用 .axf 查变量地址，然后定期去读）
```

# 三、调用的逻辑

## 3.1 分层原则：中断只采集，任务做计算

```
┌─ 中断层（微秒级，绝不能阻塞）────────────────────┐
│  USART1 中断：收 1 个字节 → 攒帧 → 拆出 16 个通道  │
│  CAN 中断   ：收 8 个字节 → 解析 → 累加角度        │
│  只做"搬运和解析"，不做任何判断和计算              │
└──────────────────────────────────────────────────┘
                       ↓ 写全局变量
┌─ 任务层（毫秒级，可以慢慢算）────────────────────┐
│  remoteTask  ：读遥控 → 判档位 → 算目标（10ms）   │
│  controlTask ：保护 → 双环 PID → 发 CAN（1ms）    │
└──────────────────────────────────────────────────┘
```

**为什么这样分：**
- 中断里**不能**调用 `osDelay()`、`printf()`、`malloc()` 这些会阻塞的函数
- 中断必须尽快返回，否则会丢数据（串口是 1 字节缓冲，CAN 是 3 深 FIFO）
- 所以中断只负责"把数据拿进来"，剩下的判断和计算都放到任务里做

**中断里具体跑了哪些代码：**

| 中断 | 入口 | 最终执行的函数 |
|---|---|---|
| CAN1_RX0 | `CAN1_RX0_IRQHandler` | `HAL_CAN_RxFifo0MsgPendingCallback` → `C620_ParseRx` → `M3508_UpdateAngle` |
| USART1 | `USART1_IRQHandler` | `HAL_UART_RxCpltCallback` → `Remote_FeedByte` →（收满时）`Remote_ParseFrame` → `GetBits` |
| USART1 出错 | 同上 | `HAL_UART_ErrorCallback` |
| TIM1_UP | `TIM1_UP_TIM10_IRQHandler` | `HAL_TIM_PeriodElapsedCallback` → `HAL_IncTick` |

## 3.2 任务的分工和优先级

| 任务 | 周期 | 优先级 | 职责 |
|---|---|---|---|
| `controlTask` | 1 ms | 40（High，最高） | 保护 + 双环 PID + 发 CAN |
| `remoteTask` | 10 ms | 32（AboveNormal） | 读遥控 + 判档位 + 算目标 |
| `debugTask` | 500 ms | 8（Low） | 绿灯心跳 |
| `defaultTask` | 1 ms | 24（Normal） | 空（CubeMX 模板自带） |

**为什么拆成两个而不是一个：**
- 考核建议"一个任务接收遥控指令，一个任务输出控制电机"
- 遥控器帧率约 14ms，10ms 读一次够了；控制要 1ms 一次
- 如果合在一起，1ms 的任务里做遥控解析会浪费 CPU，而且两个不同频率的事情混在一起不好调

**为什么 `controlTask` 优先级最高：**
- 控制周期必须是严格的 1ms，不能被别的任务拖慢
- 用 `osDelayUntil()`（绝对延时）而不是 `osDelay()`，这样周期不会累积漂移

## 3.3 模块之间的调用关系

```
main.c
  └─→ control.c（核心，唯一的"调度者"）
        ├─→ protection.c ──→ remote.c（Remote_IsOnline）
        │                 └─→ can_motor.c（M3508_IsOnline）
        ├─→ pid.c
        └─→ can_motor.c（C620_SendCurrent）

freertos.c（任务的宿主）
  ├─→ control.c（Control_RemoteUpdate / Control_Update）
  └─→ debug.c（Debug_Update）

中断（HAL 库回调）
  ├─→ can_motor.c（HAL_CAN_RxFifo0MsgPendingCallback）
  └─→ remote.c（HAL_UART_RxCpltCallback / HAL_UART_ErrorCallback）
```

**⭐ 依赖方向的原则：**

| 模块 | 依赖谁 | 被谁依赖 |
|---|---|---|
| `can_motor.c` / `remote.c` / `pid.c` | 只依赖 HAL | 被 control 调用 |
| `protection.c` | `remote.c` / `can_motor.c` / `pid.h` 的常量 | 被 control 调用 |
| `control.c` | 上面全部 | 被 freertos.c 调用 |
| `debug.c` | `control.c` / `can_motor.c` / `pid.c` | 被 freertos.c 调用 |

**下层不知道上层存在** —— 比如 `can_motor.c` 完全不知道 `control.c`，它只提供 `C620_SendCurrent()` 给别人用。

## 3.4 数据在模块之间怎么传

**全部用全局变量，不加锁。**

| 全局变量 | 定义在 | 谁写 | 谁读 |
|---|---|---|---|
| `motor1` | `can_motor.c` | CAN 中断 | controlTask、protection、debug、remoteTask |
| `remote` | `remote.c` | USART1 中断 | remoteTask、protection |
| `protect_fault` | `protection.c` | controlTask | （调试时看） |
| `pid_speed` / `pid_angle` | `pid.c` | remoteTask（Reset）/ controlTask（Calc） | debug |
| `s_mode` / `s_target_deg` / `s_stick_rpm` | `control.c`（static volatile） | **remoteTask** | **controlTask** |
| `s_rpm_cmd` / `s_last_current` | `control.c`（static） | controlTask | debug |
| `dbg_*`（5 个） | `debug.c` | controlTask | J-Scope（外部读内存） |

**为什么不需要互斥锁：**
1. 都是 32 位变量，ARM 上单条指令读写，本身就是原子的
2. 都是"**单写单读**"结构 —— 只有一个任务写它，另一个任务只读，不存在两边同时写
3. 共享的都加了 `volatile`，编译器不会把它缓存在寄存器里

**要改的规则：** 如果以后要传结构体或数组（多字节），就不能这么干，必须加锁或用队列。

## 3.5 为什么某些函数要做成钩子

`HAL_CAN_RxFifo0MsgPendingCallback` / `HAL_UART_RxCpltCallback` / `HAL_UART_ErrorCallback`
这三个函数在 HAL 库里是 `__weak`（弱符号）的空壳。

```
HAL 库不知道你想怎么处理数据 → 不能写死
但它必须在"数据到的那一刻"通知你
   ↓
方案：留一个空函数（钩子），你写一个同名的把它顶掉
      链接时会优先用你的（不带 __weak 的那个）
```

**⚠️ 函数名必须一字不差** —— 写错了编译不报错，但钩子永远是空壳，
表现为"程序跑得好好的，但收不到数据"。

## 3.6 启动时为什么是这个顺序

```
main()
  ├─ HAL_Init / SystemClock_Config / MX_*_Init      先把硬件配好
  ├─ 7 个上电自测                                    验证代码逻辑
  ├─ Control_Init()                                  初始化 PID 和保护
  ├─ C620_CanInit() / Remote_StartReceive()          ⭐ 最后才启动接收
  └─ osKernelStart()                                 启动调度器
```

**为什么自测必须在启动接收之前：**
如果先启动接收，电调的真实 CAN 帧会在自测的几十微秒里插进来，
把自测用的假数据搅乱，会出现偶发的假失败（上机时极难查）。
所以顺序是：先自测，后启动接收。

**为什么 `Control_Init()` 要在任务启动之前：**
两个任务都会用到 `pid_speed` / `pid_angle` / `protect_fault`，
必须在调度器启动前初始化好，否则任务用的就是没初始化的值。
